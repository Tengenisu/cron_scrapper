# Moneycontrol earnings scraper schedule.
#
# TESTING MODE: every 5 minutes, around the clock, with caching disabled so
# every tick regenerates its data from scratch.
#
# Two ways to run this — pick ONE, or every symbol gets queried twice:
#
#   1. This crontab (POSIX hosts). Install with:  crontab crontab.txt
#      Check with:                                crontab -l
#   2. The in-process scheduler:  npm run cron
#      Same cadence, same code path, and it works on Windows where there is no
#      crond. That is what render.yaml and the Docker/Windows notes in the
#      README use.
#
# A pass over ~8 symbols takes a couple of minutes, which is close enough to a
# 5-minute cadence that ticks can overlap. A tick that lands while the previous
# pass is still running is dropped by the lock file and prints
# {"ok": true, "skipped": true}, so nothing stacks up.

CRON_TZ=Asia/Kolkata
SHELL=/bin/bash
PATH=/usr/local/bin:/usr/bin:/bin

CACHE_ENABLED=0
MCP_ENDPOINT=http://127.0.0.1:3123/mcp

# min hour dom mon dow   command
*/5 * * * *  cd /opt/cron_scrapper && node dist/index.js --once --quiet >> /var/log/earnings/cron.log 2>&1

# Keep the JSON documents as a stream instead of only data/latest.json:
#   */5 * * * *  cd /opt/cron_scrapper && node dist/index.js --once >> /var/log/earnings/out.jsonl 2>> /var/log/earnings/err.log
#
# Back to production cadence (half-hourly, caching on):
#   CACHE_ENABLED=1
#   0,30 * * * *  cd /opt/cron_scrapper && node dist/index.js --once --quiet >> /var/log/earnings/cron.log 2>&1
#
# If n8n owns the schedule instead, use the Schedule Trigger in
# n8n-workflows/moneycontrol-earnings-scraper.json (also every 5 minutes) and do
# not install this crontab.
